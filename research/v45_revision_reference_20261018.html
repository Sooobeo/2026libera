v4.5: 출력 구조를 명확히 하는 수정

기존 실패 원본을 보존하고, 모델·디코딩·시장·기관 문서는 유지합니다. 바꾸는 것은 API에 실제 JSON Schema를 전달하는 것과 각 단계에 같은 출력 스키마를 명시하는 것입니다. 두 변경을 함께 적용하므로 각각의 효과를 따로 측정했다고 주장하지 않습니다.

근거확인한 범위
FinVector §4.1·§10스키마를 프롬프트에 명시한 금융 과제 선례. Ollama 문법 강제를 사용했다는 보고는 없고 원 평가 프롬프트는 비공개입니다.
Ollama 공식 문서format=json과 실제 스키마 객체 전달을 구분하며, 스키마를 프롬프트에도 제시하도록 권고합니다.
v0.35.1 구현기본 JSON 모드는 임의 키를 허용하지만, 스키마는 필요한 필드와 자료형을 제한합니다.

산업 코드 11개와 기존 필드는 구조로 지정할 수 있습니다. 그러나 산업별 등급, 출처 정답, 비중, 올바른 근거 ID를 미리 넣지 않습니다. 특히 11개 행을 만들게 해도 산업 코드 중복·누락, 비중 합계, 이유의 타당성은 별도 검증해야 합니다.

고정된 llama.cpp b11232 문서와 구현 사이에 tuple 지원 설명 차이가 있어 이번에는 해당 기능을 사용하지 않습니다. 단순 배열·필드 구조만 사용하고, 수치 범위·합계·중복 검사는 유지합니다. 실행 성공과 전략 타당성은 별개이며, 새 조건에서의 완료 여부는 아직 검증되지 않았습니다.
