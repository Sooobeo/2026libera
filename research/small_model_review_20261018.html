이번 조사에서는 설치·추론·원격 설정 변경을 하지 않았다. 기존 실험계획·소논문·실행 설정은 v4.2 상태이며, 이 문서는 변경 후보와 근거를 별도로 기록한다.

2. 금융 점수가 말해 주는 범위

Data-Centric Post-Training(2026-09-09), §5·Table 3의 동일 778문항 평가에서 원본 Qwen3.5-4B는 75.2, Qwen3-4B는 61.0, Qwen3-1.7B는 56.0이었다. 모델별 추론 설정이 적용됐고 GPT-5.2가 정오를 채점했다. 이 수치는 후보 선정의 보조 근거이며, 우리 산업 배분 과제의 성공률·수익률·양자화본 성능으로 바꿔 읽을 수 없다. 본문에 나온 temperature 0과 32,768토큰은 채점 모델 설정이다. 평가대상 Qwen의 상세 생성 조건은 확인되지 않는다.

FinVector-Market-4B(2026-10-06), §4.1·6.4·7.3·10는 Qwen3.5-4B 원본과 추가 학습 모델을 구분해 평가했다. 원본에도 명시적 JSON 구조를 제공했으며, greedy decoding·thinking 비활성화·최대 700토큰을 사용했다. 명시적 구조를 받은 원본에서도 23/600개 출력이 상한에 도달했다. 비공개 평가 자료, 학습·평가 문서 중복, 일부 정답 수치 오류라는 한계가 있다. 이 연구는 구조화 응답과 non-thinking 실행의 선례가 되지만 700토큰이 우리 과제에 충분하다는 근거는 아니다.

3. 설치 크기는 작아도 전체 실험은 별도 확인이 필요하다

10월 17일 읽기 전용 확인 기록상 서버 컨테이너는 RAM 8 GiB, CPU 4개 할당이며 GPU가 노출되지 않았다. 물리 호스트는 약 16 GiB RAM의 Pentium G6405이고 다른 작업과 자원을 공유한다. 실제 공유 저장 풀의 잔여 공간은 당시 약 23.14 GiB였다. 3.32 GB 다운로드는 기존 약 22.62 GB 후보보다 저장 부담이 작지만, 현재 여유 공간은 실행 전에 다시 확인해야 한다. 현장 확인 기록

메모리에는 모델 파일 외에도 이전 문장을 처리하는 캐시와 실행 버퍼가 필요하다. 공식 구조에 f16 캐시·단일 시퀀스를 가정한 full-attention KV 부분만 계산하면, 32,768토큰에서 Qwen3.5-4B는 약 1 GiB, 원래 Qwen3-4B는 약 4.5 GiB, Qwen3-1.7B는 약 3.5 GiB다. 이는 구조를 이용한 설명용 추정이며 총 RAM 실측이 아니다. 가중치·선형 attention 상태·버퍼·실행기 정책은 제외한다. 따라서 파일이 가장 작은 모델이 긴 실험에서도 메모리를 가장 적게 쓰는 것은 아니다. 3.5-4B 구조 · 원래 4B 구조 · 1.7B 구조

Qwen3.5-4B 배포 config의 최소 Ollama 버전은 0.30.0으로, 확인된 서버 버전 0.35.1은 이 선언 조건을 충족한다. 실제 로딩·CPU 실행·긴 문맥의 정상 동작까지 확인한 것은 아니다. 네 단계 동안 쌓인 최종 응답·기관 문서·계산 피드백을 유지한 전체 예비실험이 필요하다.

우선 검토할 실행안		FinVector 원본 모델 평가의 실제 모드. Ollama에서는 temperature 0이 대응하는 후보지만 동일 엔진의 재현은 아니다.별도 내부 추론 생성 없이 명시적 해석·대안·배분·재검토를 수행한다. 네 단계 구조는 유지된다. 총 소요시간 감소 가능성은 실측해야 한다. 기존 thinking 조건에서 바뀐 점은 프로토콜에 기록한다.
B. Qwen3.5-4B / thinking 켬기존 PortBench의 추론 조건을 참고하거나 해당 모델의 공식 권고를 적용하는 별도 선택내부 추론 토큰이 출력 예산과 시간을 쓴다. PortBench의 temperature 0이 이 작은 모델의 적절한 조건으로 검증된 것은 아니다. 공식 카드 설정은 논문 실험값과 구분한다.

PortBench §3.1의 8,192토큰 출력 한도는 기존 설계의 출처다. 이를 새 모델에 유지한다면 다른 모델·과제로 옮긴 연구자 선택으로 기록해야 한다. FinVector의 700이나 제조사의 권장값을 섞어서 하나의 논문을 그대로 재현했다고 쓰지 않는다. 한도 도달은 실패 기록에 남기며 자동 재시도·출력 수정을 하지 않는다. 구체적인 출력·문맥 예산은 네 단계 pilot으로 검증한 뒤 본실험 전에 고정한다.

문맥 32K는 네 단계의 최대 출력 이력을 모두 담는다고 보장할 수 없다. 과거 최종 응답 세 개와 새 출력에 각 8,192토큰을 허용하면 그것만으로 32,768이므로 원문 입력이 들어갈 자리가 없다. 현재 코드의 UTF-8 상계도 실제 tokenizer 토큰 수와 다르다. 실제 대화 템플릿에 맞춘 길이 확인이 필요하며, 편의를 위해 이력을 삭제하거나 요약하면 비교 조건이 달라진다. 과거 내부 thinking의 보존 여부와 명시적 응답 보존도 구별한다.

5. 소논문 주제와 다음 단계

같은 소형 모델·양자화·추론 설정·시장 자료·계산 지원을 R1과 R4에 공통 적용하면, “기관 자료를 처음 제공할 때와 마지막에 제공할 때 그 기관의 판단을 얼마나 보존하는가”라는 질문은 유지된다. 다만 결과는 그 모델과 공개 문서 사례의 관찰이다. 두 조건 모두 과제를 수행하지 못하면 절차 효과가 없다고 단정할 수 없다. AI 전반이나 실제 금융기관 전체의 획일화로 일반화하지 않는다.

  1. Qwen3.5-4B Q4_K_M을 우선 진단 후보로 기록하고 정확한 모델·버전·설정을 고정한다.
  2. 짧은 합성 입력으로 로딩·메모리·시간·종료·JSON 동작을 점검한다. 기술 점검을 실험 결과로 계산하지 않는다.
  3. 이전 시점의 문서로 R1/R4 네 단계 pilot을 수행한다. 문맥 보존, 출력 완결성, 근거 해석을 확인한다.
  4. 실패·설정 변경 기록을 남기고 실행기·계획·소논문을 함께 수정한 뒤 본실험 기준을 동결한다. R1/R4 차이가 크게 나온 모델을 선택 기준으로 삼지 않는다.

이번 조사로 확정된 것은 후보 선정의 근거와 확인할 항목이다. 설치 완료·실행 적합성·본실험 준비 완료를 뜻하지 않는다. 단계별 실제 AI 결과는 아직 없다.
